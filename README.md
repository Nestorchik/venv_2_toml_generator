# Генерация TOML для UV из .VENV для снятия их "слепка"

Утилита предназначена для генерации файла **pyproject.toml** из текущего виртуального окружения (.venv) ComfyUI и аналогичных PY-проектов.

Различает версии **Torch** для **CPU** и для **CUDA** и генерирует соответствующие описания в **toml**-файле.

В основном удобна для тех, кто использует менеджер UV вместо PIP. Технология заменяет метод создания VENV путем импорта "**requirements.txt**" через "**pip install -r requirements.txt**".

Идеология работы:

- поместить **venv2toml.py** в папку рядом с окружением с именем "**.venv**" _(стандартное для UV!)_
- проследить, чтобы в папке отсутствовали старые файлы **pyproject.toml** и **uv.lock** (!!!)
- запустить "**uv run venv2toml.py**"
- скрипт прочитает "**.venv**" и сгенерирует новый **pyproject.toml**
- последующее восстановление "**.venv**" при переносе или после удаления производится командой "**uv sync**"
- менеджер **UV** выполняя команду "run" при обнаружении в текущей папке файла **pyproject.toml** всегда будет проверять соответствие версий пакетов в "**.venv**" описанному в TOML-файле.

Текущий код хорош тем, что он абсолютно самодостаточный и не требует установки дополнительных пакетов.

Преимущества:
- Нет внешних зависимостей — достаточно стандартного Python.
- Работает сразу в любом виртуальном окружении (если указать путь к venv).
- Гибкость — можно подставлять URL, маркеры платформ, дату/время, зависимости.
- Прозрачность — весь TOML формируется через обычные строки, легко править под свои нужды.
- Совместимость с UV — генерируемый файл сразу валиден и uv sync его корректно читает.

Недостатки:
- Формирование TOML через f-строки менее “безопасно” по сравнению с библиотеками типа toml или tomli-w (например, если имена пакетов содержат кавычки или спецсимволы).
- Нет автоматической проверки структуры TOML.
- В моем случае это преимущество: скрипт лёгкий, не требует установки чего-либо и сразу работает с UV.
